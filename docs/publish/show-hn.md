## Body

Hi HN,

I built Lyric Motion Studio, an open-source text-to-video pipeline for vertical shorts.

The unusual part: **frames are not generated by a text-to-image model**. Each shot is a complete SVG written by DeepSeek (a text model), then rasterized with headless Chrome at 1080×1920. No GPU, no per-image API fees, and you get precise control over text, arrows, comparison charts and leader lines inside each frame — which matters a lot when every shot has to match a specific line of narration.

The rest is deliberately boring: Edge-TTS for narration, ffmpeg for rendering, local everything.

Measured on a real 3-minute video (23 shots):
- 29 LLM calls, ~119k tokens
- ≈ $0.11 in model cost
- ≈ 5.8 minutes on a regular CPU
- 21.7 MB output

Features beyond the core pipeline: target-duration script expansion/trimming (instead of slowing speech), automatic opening line, 1.3× default narration rate, subtitle safe areas for the Douyin player UI, auto-generated poster covers, a publishing pack (video/cover/title/description/hashtags), and a daily mode.

Quick test without any API key:

```bash
npm ci
npm run demo
```

Or run it in Docker (Node 24 + ffmpeg + Chromium + CJK fonts baked in).

Repo (MIT): https://github.com/a18334761226-spec/lyric-motion-studio

Happy to answer questions about the SVG-frame approach, subtitle timing, or the cost math. Feedback I'm most interested in: would you use this for narration/knowledge videos, or is it too niche?
